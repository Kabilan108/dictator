Current design decisions and open questions

Cursor is the selected logo. No tray status label or separate recording popup. The main window shows recording/transcribing activity immediately left of search and hides it for idle and terminal states. Complete/Fail controls in the design sidebar finish a simulated recording, reveal it in history and select it, clearing filters when necessary. Re-type has been removed.

Configuration proposal: keep Home Manager-owned config.json read-only. Store only explicitly app-owned preferences, such as microphone ordering, in a separate preferences.json. Avoid overlapping fields and implicit overrides. This split and daemon reload semantics are not implemented. A wholly mutable config is an alternative, but would require changing the module's current ownership of config.json.

Microphone behavior follows Sotto's priority policy: the first connected preferred input wins; disconnected devices retain their order; use the system default when no preference is available. Resolve on the next recording and never switch an active capture automatically.

Retry in the current Rust implementation creates a new transcript ID and timestamp, then deletes the failure row. Proposed GUI behavior, simulated here: retain recording ID and capture time, append attempts with their own completion time, model, result and error. Both retry success and failure reveal and select the original recording without reordering its capture chronology.

Revision proposal remains: preserve original text as revision 0, append full revision snapshots, and compute bounded word diffs on demand. Keep current text/version cached for CLI compatibility, and use transactional expected-version checks. Neither this schema nor retry attempt storage has been migrated.
